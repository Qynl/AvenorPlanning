# Plant Loadouts and Ability Sets

**Status:** PROPOSAL

## Core rule
A plant grants a complete ability set. The player equips a limited selection of discovered sets and uses the abilities belonging to those sets.

## Proposed loadout structure
- A small number of equipped plant sets.
- Each equipped set exposes its full ability sequence.
- Players can save named loadout presets.
- Loadouts can be changed in safe preparation areas or at designated world stations.
- Encounters should not force a player to own one specific rare plant.

Exact slot count and ability input layout remain TBD.

## Set identity
A loadout should create a coherent combination of exploration, support, defence and encounter tools. Avoid reducing plants to interchangeable single buttons.

## Switching and cooldown rules
- Define whether cooldowns persist when switching sets.
- Prevent switching from instantly refreshing abilities.
- Make current set and cooldown state clear in the HUD.
- Provide controller and mobile layouts from the start.

## Data integrity
The server validates owned plant IDs, unlocked ability IDs, loadout slot limits and switch restrictions. Clients may request changes but cannot grant themselves abilities.

## Future extensions
Preset sharing, cosmetic loadout cards and practice previews are possible, but not required for the first playable version.
